3. ДОКУМЕНТУВАННЯ ПРІОРИТЕТУ ЗНАЧЕНЬ (VALUE PRECEDENCE) У HELM (TASK 6.C)
================================================================================

3.1 Ієрархія пріоритетів значень у Helm:
Коли Helm рендерить шаблони, він об'єднує значення (deep-merge) з кількох джерел з чітко визначеним пріоритетом (від найнижчого до найвищого):

   [ Рівень 1 (Найнижчий) ]
   Базовий файл `values.yaml` всередині самого чарта.
   Визначає безпечні значення за замовчуванням (default values).
               │
               ▼
   [ Рівень 2 (Середній) ]
   Користувацькі файли значень, передані через ключ `-f` / `--values` (наприклад, `-f values-prod.yaml`).
   Якщо передано декілька файлів `-f` (`-f dev.yaml -f override.yaml`), пріоритет має файл, зазначений пізніше в командному рядку (правило rightmost wins).
               │
               ▼
   [ Рівень 3 (Найвищий) ]
   Індивідуальні параметри, передані через командний рядок:
   `--set`, `--set-string`, `--set-file`, `--set-json`.
   Вони перекривають будь-які значення як з `values.yaml`, так і з файлів, переданих через `-f`.

3.2 Практична демонстрація перекриття значень на прикладі users.replicas:

Крок 1: Базове значення за замовчуванням із values.yaml:
$ helm template devops-release helm/devops-platform -s templates/services/users/deployment.yaml | grep "replicas:"
  replicas: 2

Крок 2: Перевизначення через файл середовища values-prod.yaml (-f):
$ helm template devops-release helm/devops-platform -f helm/devops-platform/values-prod.yaml -s templates/services/users/deployment.yaml | grep "replicas:"
  replicas: 3

Крок 3: Перевизначення значення як з values.yaml, так і з values-prod.yaml через прапорець --set:
$ helm template devops-release helm/devops-platform -f helm/devops-platform/values-prod.yaml --set users.replicas=5 -s templates/services/users/deployment.yaml | grep "replicas:"
  replicas: 5

Результат:
Значення `--set users.replicas=5` має абсолютний пріоритет над файлом `-f values-prod.yaml` (3) та над дефолтним `values.yaml` (2).

================================================================================

4.1 Опис реалізованого рішення:
В межах завдання 9.b реалізовано два ключові механізми забезпечення надійності релізів Helm:
1. Тест релізу (`templates/tests/test-health.yaml`): декларативна перевірка працездатності всіх мікросервісів після встановлення або оновлення релізу (`helm test`).
2. Хук життєвого циклу (`templates/hooks/pre-upgrade-backup.yaml`): запуск перевірочного завдання (`Job`) перед початком застосування оновлення до існуючого релізу (`helm.sh/hook: pre-upgrade`).

4.2 Тест працездатності релізу (Health Check Test):
Файл: `helm/devops-platform/templates/tests/test-health.yaml`
- Kind: Pod
- Аннотації:
  `helm.sh/hook: test` — ідентифікує под як тестовий люфт для виклику `helm test`.
  `helm.sh/hook-delete-policy: before-hook-creation,hook-succeeded` — автоматично очищує тестовий под при повторному запуску або успішному проходженні.
- Образ: `curlimages/curl:8.5.0`
- Логіка: Послідовно виконує HTTP GET запити з таймаутом до кінцевих точок `/health`:
  - `http://gateway:8000/health`
  - `http://users:8001/health`
  - `http://products:8002/health`
  - `http://orders:8003/health`
  У разі успішної відповіді (код 200) від усіх сервісів скрипт повертає exit code 0. Якщо бодай один сервіс повертає помилку або не відповідає, скрипт негайно завершується з ненульовим кодом помилки завдяки режиму `set -e`.

Маніфест тесту:
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: "{{ include "devops-platform.fullname" . }}-test-health"
  labels:
    {{- include "devops-platform.labels" . | nindent 4 }}
  annotations:
    "helm.sh/hook": test
    "helm.sh/hook-delete-policy": "before-hook-creation,hook-succeeded"
spec:
  restartPolicy: Never
  containers:
    - name: test-health
      image: curlimages/curl:8.5.0
      imagePullPolicy: IfNotPresent
      command:
        - /bin/sh
        - -c
        - |
          set -e
          echo "=== Running Helm Test Health Check ==="
          echo "1. Checking Gateway health (http://gateway:{{ .Values.gateway.service.port | default 8000 }}/health)..."
          curl -fsS --max-time 10 http://gateway:{{ .Values.gateway.service.port | default 8000 }}/health
          echo ""

          echo "2. Checking Users service health (http://users:{{ .Values.users.service.port | default 8001 }}/health)..."
          curl -fsS --max-time 10 http://users:{{ .Values.users.service.port | default 8001 }}/health
          echo ""

          echo "3. Checking Products service health (http://products:{{ .Values.products.service.port | default 8002 }}/health)..."
          curl -fsS --max-time 10 http://products:{{ .Values.products.service.port | default 8002 }}/health
          echo ""

          echo "4. Checking Orders service health (http://orders:{{ .Values.orders.service.port | default 8003 }}/health)..."
          curl -fsS --max-time 10 http://orders:{{ .Values.orders.service.port | default 8003 }}/health
          echo ""

          echo "=== All services passed health checks successfully! ==="
          exit 0
```

Команда виконання тесту в кластері:
$ helm test devops-release

4.3 Хук попередньої перевірки та резервного копіювання (Pre-Upgrade Hook):
Файл: `helm/devops-platform/templates/hooks/pre-upgrade-backup.yaml`
- Kind: Job (batch/v1)
- Аннотації:
  `helm.sh/hook: pre-upgrade` — спрацьовує автоматично після виклику `helm upgrade`, але ДО внесення будь-яких змін у розгорнуті поди або сервіси.
  `helm.sh/hook-weight: "1"` — визначає черговість виконання (виконується в порядку зростання ваги).
  `helm.sh/hook-delete-policy: before-hook-creation,hook-succeeded` — видаляє старий Job перед створенням нового та видаляє успішно завершений Job для запобігання накопиченню сміття.
- Образ: `busybox:1.36`
- Призначення: Імітує перевірку готовності схеми БД, зняття резервної копії перед міграціями та фіксацію часової мітки оновлення. Якщо Job зазнає збою (failure), оновлення релізу Helm блокується, зберігаючи стабільність продакшн-середовища.

Маніфест хука:
```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: "{{ include "devops-platform.fullname" . }}-pre-upgrade-backup"
  labels:
    {{- include "devops-platform.labels" . | nindent 4 }}
  annotations:
    "helm.sh/hook": pre-upgrade
    "helm.sh/hook-weight": "1"
    "helm.sh/hook-delete-policy": "before-hook-creation,hook-succeeded"
spec:
  backoffLimit: 1
  template:
    metadata:
      name: "{{ include "devops-platform.fullname" . }}-pre-upgrade-backup"
      labels:
        {{- include "devops-platform.labels" . | nindent 8 }}
    spec:
      restartPolicy: Never
      containers:
        - name: pre-upgrade-backup-validation
          image: busybox:1.36
          imagePullPolicy: IfNotPresent
          command:
            - /bin/sh
            - -c
            - |
              echo "=========================================================="
              echo "[PRE-UPGRADE HOOK] Running pre-upgrade backup & validation"
              echo "=========================================================="
              echo "[PRE-UPGRADE HOOK] Current timestamp: $(date -u +'%Y-%m-%dT%H:%M:%SZ')"
              echo "[PRE-UPGRADE HOOK] Verifying database connectivity & schema integrity..."
              echo "[PRE-UPGRADE HOOK] Simulating database snapshot / state backup..."
              echo "[PRE-UPGRADE HOOK] Pre-upgrade safety checks passed successfully."
              exit 0
```
